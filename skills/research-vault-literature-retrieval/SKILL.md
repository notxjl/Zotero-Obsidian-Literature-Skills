# Obsidian Literature Retrieval

## 工作区

使用用户明确指定的 Obsidian Vault；未指定时，从当前工作目录向上查找最近的、包含以下结构的工作区：

```text
indexs/文献索引.md
notes/
templates/paper-template.md
```

默认只读。只有用户明确要求修改笔记或索引时才写入。

## 检索顺序

1. **索引定位**：先读 `indexs/文献索引.md`，按领域、题名、作者、年份、会议/期刊、任务或 Zotero Key 缩小候选。
2. **笔记理解**：读取候选论文对应的 `notes/` 文件，比较研究问题、方法、数据、结论、局限和用户判断。
3. **回到来源**：涉及作者原话、定义、公式、模型细节、数值、图表或页码时，通过笔记中的 Zotero Key 或附件入口读取 Zotero 全文/PDF。
4. **回答**：区分“索引元数据”“笔记归纳”“原文核验”三种证据层级。

如果用户明确要求“基于当前项目文件检索”或类似表述，必须先搜索当前实际文件，不得依赖模型记忆、旧会话或文件名印象。

## 证据规则

- 索引只用于定位和元数据，不能单独证明论文内容。
- 中文笔记可以支持高层理解和跨论文比较，但不能反向生成英文引语。
- 原文引语只能来自可访问的全文或 PDF；无法核验时直接说明。
- PDF 页码只有经过实际页面核验或可靠映射后才能给出。
- 笔记中的“分析者评注（非原文）”和“我的评注”不能当作论文事实、作者观点或写作依据。
- 笔记中的“原文未涉及”“作者未报告”“当前材料未定位”和“不适用”含义不同；回答时保留这种区别，不得把材料缺口说成论文没有讨论。
- 同一论文通过 `zotero_key` 去重。
- 默认只使用当前 Vault 和 Zotero 来源；用户明确要求外部检索时才联网。

## 输出

回答中给出实际使用的论文题名和笔记链接；需要精确证据时补上 Zotero Key、全文/PDF 位置和核验状态。不要用大量原始 Key 代替可读的论文名称。
