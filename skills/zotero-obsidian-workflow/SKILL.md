# Zotero Obsidian Workflow

## 目标

把用户指定的 Zotero 分类同步到当前 Obsidian 项目：

```text
Zotero 分类
  -> 当前文献快照
  -> 与单文件索引比较
  -> 报告新增、移出、缺笔记和异常
  -> 按用户模板逐篇生成或补全笔记
  -> 重建完整文献索引
```

本 Skill 只处理用户明确指定的分类或文献。不得自行扩大范围、下载论文、整理整个 Vault 或修改 Zotero。

## Vault 契约

先解析本次 `vault_root`。默认使用当前 agent 打开的 Obsidian 项目：从当前工作目录向上查找最近的、包含 `indexs/`、`notes/`、`templates/` 的项目根目录。用户明确指定其他项目时才切换。全局 `config.toml` 只提供 `zotero_data_dir`，不保存 Vault 路径。

Vault 只允许以下三个顶层工作目录：

```text
<vault_root>/
├── indexs/
│   └── 文献索引.md
├── notes/
└── templates/
    └── paper-template.md
```

- 新内容只能写入上述三个目录。不要创建其他顶层目录。
- 索引固定为一个文件：`indexs/文献索引.md`。
- 新笔记只放在 `notes/<领域>/<论文标题>.md`。领域目录只是 `notes/` 下的组织层，不增加新的顶层目录。
- 模板唯一来源是 `templates/paper-template.md`。每次创建或实质修改笔记前都必须重新读取它；不得覆盖、迁移或“升级”用户模板。

如果三个目录、索引文件或模板缺失，先报告具体缺失项。模板缺失时停止生成笔记，不得用模型自拟结构代替。

## 工作原则

- Zotero 分类的当前成员关系是本次同步的事实来源；`indexs/文献索引.md` 是上次活动文献集合。
- 以 Zotero 父条目 `zotero_key` 作为稳定身份，不以标题、文件名或作者作为主键。
- 默认处理用户点名分类中包含子分类的文献。只有用户明确说“不包含子分类”时只处理该分类下的直接文献。
- 先完成并展示变更检查，再进行笔记写入和索引更新。不要先改文件再倒推差异。
- 一篇论文对应一篇独立笔记，不把多篇论文合并成综合笔记。
- 对已有笔记做增量补全，不覆盖用户自行撰写的判断、问题和批注。除非用户明确要求重写，否则保留已有正文中可确认属于用户的内容。
- 从分类移出的文献默认只从活动索引移除，不删除笔记。只有用户明确要求删除对应笔记时才删除。
- 不根据标题猜 Zotero Key，不根据中文笔记反写英文原文，不为缺失信息编造页码、引语、期刊或结论。
- 写正文前先判定论文类型。方法、系统、实证、分析、benchmark、survey、理论、立场和资源型论文使用不同章节，不得把非方法论文强行写成“backbone + 模块 + 消融 + latency”结构。
- 严格区分原文事实、作者主张、分析者评注和用户批注。AI 生成内容不得冒充作者观点。
- 统一使用模板定义的空缺状态：“原文未涉及”“作者未报告”“当前材料未定位”“不适用”。没有访问到全文时不得写成“原文未涉及”。

## 第一步：解析同步范围

确认以下信息：

1. Vault 根目录。
2. Zotero 分类名称或分类 Key。
3. 是否包含子分类。
4. 是否只检查、是否同时生成缺失笔记、是否要求重写已有笔记。

分类名称重复时停止并要求用户提供分类 Key。用户只给出模糊分类名时，不得自行选择最接近的一项。

读取 `indexs/文献索引.md` 时，提取每行的 `Zotero Key`、`Zotero 分类`、`笔记` 和 `领域`。索引缺失时视为首次同步，并明确说明：没有旧索引就无法可靠识别历史移出项。

## 第二步：获取当前分类快照

优先使用当前环境可用的 Zotero MCP integration。没有可用 MCP 或需要稳定的本地快照时，运行本仓库工具：

```powershell
python tools/zotero_collection_snapshot.py --collection "<分类名或 Key>"
```

需要递归子分类时增加 `--include-subcollections`。

需要单篇论文的批注、Zotero Notes、PDF 附件和全文缓存时，按 [zotero-data-fetcher](../zotero-data-fetcher/SKILL.md) 读取。

快照至少确认：`zotero_key`、标题、作者、年份、具体会议/期刊、DOI、文献类型、分类、标签、附件、批注和可访问全文。缺失字段保留为空或标记未定位，不得推断。

## 第三步：先报告变更

只对 `Zotero 分类` 属于本次同步范围的索引行做移出判断。若旧行没有分类信息，可用对应笔记 frontmatter 的分类字段、链接或用户确认补足；仍无法判断时不要自动认定为移出。

至少输出：

```text
同步分类：<分类>
当前文献：<n>
索引原记录：<n>
新增：<n>（逐条列出标题和 Zotero Key）
移出：<n>（逐条列出标题和 Zotero Key；说明笔记是否保留）
已有索引但缺少笔记：<n>
身份或元数据冲突：<n>
```

标题重名但 Key 不同、索引 Key 重复、笔记被多个 Key 引用、分类无法唯一解析时，将对应文献标为异常并停止该项写入。

## 第四步：逐篇生成或补全笔记

对每篇新增文献，以及索引中存在但笔记缺失的文献：

1. 读取 `templates/paper-template.md`。
2. 读取可用元数据、Zotero 批注、Zotero Notes、全文缓存、附件正文或 PDF。
3. 根据研究问题、贡献和证据结构确定 `primary_paper_type` 与 `paper_types`，再判断哪些模板章节适用。
4. 严格沿用模板的 frontmatter、可见章节、标题层级、表格和区块顺序；填写实际内容，不保留示例行。
5. 贡献、研究问题、关键模块、baseline、指标和主要发现均按原文实际数量记录，不强行凑三条，也不因某一类内容缺失而补写常识。
6. 对每个空缺使用准确状态：“原文未涉及”“作者未报告”“当前材料未定位”或“不适用”。没有访问到全文、附录、图表或页码时使用“当前材料未定位”。
7. 说明性文字只写原文可直接核验的事实或作者明确提出的主张。不得自行添加研究意义、因果解释、替代解释或批判性评价。
8. “分析者评注（非原文）”默认留空；只有用户明确要求批判性评价时才填写，并保持醒目标记。
9. “我的评注”只属于用户。新建笔记时留空；更新已有笔记时原样保留，不得填写、改写、移动、概括或删除。
10. 保留真实 Zotero 入口、全文入口或附件入口；只写当前环境确认存在或可打开的链接。
11. 新建笔记后检查模板占位符、YAML、链接、公式、标题层级、空缺状态和论文类型是否一致。

已有笔记按以下顺序更新：

1. 先检查笔记 frontmatter 中的 `zotero_key` 和当前索引链接是否一致。
2. 保留用户已经完成的研究判断、问题、私有批注和“我的评注”。
3. 只补全缺失的模板章节、元数据、可核验证据和错误的真实链接。
4. 如果为适配模板必须重排正文，保留原意与用户文字；无法安全合并时停止并报告冲突。

不要为了统一格式批量重写所有未变化笔记。用户明确要求“重写全部笔记”时才重写。

## 第五步：重建完整单文件索引

笔记完成后重建 `indexs/文献索引.md`。必须遵守 [references/index-schema.md](references/index-schema.md)。

索引是一个文件，但按“领域”拆分章节；不同领域不能混在同一张表里。每篇文献只进入一个主要领域，避免重复计数。已有领域分类默认保持不变，只有明确的新证据或用户要求才改类。

至少包含标题、作者、年份、领域、具体会议/期刊、任务、文献类型、DOI、Zotero Key、Zotero 分类和笔记链接。索引必须覆盖当前索引应保留的全部活动文献，而不只是本次新增文献。

重建时保留其他 Zotero 分类对应的索引行，只更新本次分类的成员关系、元数据和笔记链接。若无法安全保留旧行，停止写索引并报告原因。

## 第六步：完成检查

写入后逐项确认：

- 索引只有一个文件，且位于 `indexs/文献索引.md`。
- 每个索引行都有真实 `zotero_key`；没有重复 Key。
- 每个笔记链接都指向 `notes/` 中真实存在的文件。
- 每个新增或补全笔记都使用 `templates/paper-template.md` 的结构。
- 没有残留模板占位符。
- 每篇笔记都声明论文类型和材料状态，且空缺状态与证据范围一致。
- “分析者评注（非原文）”没有冒充作者观点，“我的评注”未被 AI 写入或改写。
- 移出文献没有出现在活动索引中，且未被擅自删除。
- 索引领域章节完整，且没有把不同领域混在同一张表。
- 本次新增、移出、新建笔记、补全笔记、异常和保留笔记数量一致可解释。

最后向用户简要报告同步分类、新增/移出清单、实际写入的笔记、索引更新结果和未解决问题。
